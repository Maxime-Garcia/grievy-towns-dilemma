### BUG 2 — Inventaire freeze : ESC bloque le jeu après équipement

**Symptôme :** Ouvrir l'inventaire → équiper un item → tenter ESC → jeu bloqué. La touche I ne répond plus. Seul le bouton "[I] Fermer" (clic) fonctionne, mais après retour le jeu est complètement gelé (plus aucun input).

**Cause racine identifiée :** `showItemDetail()` appelle `scene.restart({ gameScene })` après équipement. Pendant le `restart()`, la scène est brièvement en état `LOADING/BOOTING` : `scene.isActive('InventoryScene')` retourne `false`. À ce moment, si l'ESC est pressé dans GameScene (dont les keyboard listeners restent actifs même en état paused), le handler ne trouve pas InventoryScene active et essaie d'ouvrir PauseScene → les deux scènes se superposent. Quand InventoryScene finit son restart, `shutdown()` n'a pas été appelé → `setPaused(false)` n'a pas tourné → jeu définitivement gelé.

**Fix recommandé :** Ne pas utiliser `scene.restart()` dans `showItemDetail()`. À la place, après équipement/vente :
1. Détruire le panel de détail
2. Appeler `renderGrid()` et `renderEquipment()` en tant que méthodes idempotentes (pré-cleaner leurs objets)
3. OU stocker tous les objets créés dans des arrays de classe et les detruire/recreer via une méthode `refresh()`

**Alternative rapide :** Dans `showItemDetail()`, remplacer `scene.restart()` par :
```typescript
panel.destroy();
this.children.removeAll(true);  // détruit tout
this.create();                   // relance le create manuellement
```
(moins propre mais évite le lifecycle Phaser)

**Fichier :** `src/scenes/InventoryScene.ts`, méthode `showItemDetail()`, lignes 235 et 240.

### BUG 3 — Attaques non fonctionnelles (touche J et clic souris)

**Symptôme :** Appuyer sur J ou clic gauche ne déclenche pas d'attaque.

**Cause probable :** Conséquence directe du BUG 2 — si le jeu reste bloqué en état `paused`, `GameScene.update()` ne tourne plus → `handleAttackInput()` (qui utilise `JustDown()` dans update) n'est jamais appelé. Le listener clic souris vérifie `!this.sys.isPaused()` → `true` → skip.

**Fix :** Résoudre BUG 2 en priorité. Une fois le freeze corrigé, vérifier que J fonctionne en dehors du contexte freeze en ajoutant un listener direct (hors update) :
```typescript
// Dans setupInput(), après la création de attackKey
this.attackKey.on('down', () => {
  if (!this.sys.isPaused() && !this.isInDialogue) this.performBasicAttackOrInteract();
});
```
Actuellement l'attaque passe par `handleAttackInput()` dans `update()` — ajouter aussi un listener `on('down')` direct comme les autres touches de menu.

**Note debug :** Le "mode debug des timings de frappe" (fenêtres de tir visibles) avait été mentionné. À implémenter une fois les attaques fonctionnelles — probablement un overlay `Phaser.GameObjects.Rectangle` semi-transparent sur hitbox + log console de chaque `JustDown` et de la durée de la frame d'attaque.
